# AL六角海战 · 多势力回合海战原型

目前已完成12艘代表舰船、超大六角海图、多势力回合、玩家/AI席位、框选与共同移动、原素材弹道、独立实时航空中队、战争迷雾、港口占领、资金收入、维修增援、胜负结算与存档。可建立2～8方战局；玩家与AI可以混合，未启用席位为空位，联网将在后续阶段实现。

框选版本的实际浏览器检查见 [框选与共同移动报告](output/box-selection-browser-verification.json)，舰船与舰机混合选择截图保存在 `output/screenshots/box-selected-ships.png` 和 `output/screenshots/box-selected-mixed-units.png`。

所有对局阵营使用同一舰船池，当前每方各有完整12艘，不受白鹰、皇家等原作身份限制。默认四方共48艘，八方共96艘，分布在各自的集结海域。舰船与飞机直接在海图点击或框选，仅能指挥本方单位。

界面不显示舰船总列表或飞机总列表，右侧仅显示当前选中单位或当前多选的信息。选中飞机时显示本中队的行动力、机体、续航、弹药、任务、母舰及返航操作；切换选舰或取消选择后清除飞机详情。石油与回合操作固定在右下角，小地图浮动在左下角。720像素及以下窗口使用“单位信息”按钮打开可收起的面板，同时保留小地图与回合操作。

双击 `启动海图.bat`，打开 `http://127.0.0.1:18768/`。保持启动窗口运行，关闭窗口即可停止服务。本机工作区已有构建好的 `dist/`，日常运行只需要本机Python 3，不需要安装Node、npm或访问互联网。从 GitHub 新克隆时需先执行 `npm ci` 和 `npm run build`，因为 `dist/` 不纳入 Git。

## 海图操作

- 左键拖框选择本方舰船和飞行中队；Shift / Ctrl追加框选或点击追加、取消单个单位。点击空白或Esc清空选择。
- 鼠标中键拖动海图，也可Alt＋左键拖动，或用WASD / 方向键平移。
- 滚轮缩放，或使用右下角加减按钮；缩放以鼠标所在位置为中心。
- 点击海图中的本方小人或飞机选中单位，也可框选；使用“下一艘”或Tab定位待指挥舰船。
- 点击或拖动小地图定位远处海域，点击“全图”查看整个地图。
- 点击“返回舰队”或按空格返回当前势力舰船，镜头按窗口大小调整。
- 使用“六角网格”或G切换格线；M查看全图；Esc取消选择。
- 暂停/恢复表现动画，或切换选中小人的左右朝向。
- 从主界面进入“单人对战”或“本地对战”，选择128×128、256×256、512×512海域、2～8个启用席位及每席位的玩家/AI控制方式。未启用席位显示为空位；原战局保留在“读取 → 上一战局”，手动存档不会被覆盖。目前各规模的地形由固定、可重复的生成规则产生。

近处使用骨骼小人，缩远后使用舰种图标。海面、深海、浅滩、岛屿和岸线为代码绘制的原型图形，后续可逐步替换美术素材。单舰选中时，绿色海格表示本回合可抵达范围，绿色路径预览只表示当前这次移动。多选时每个选中单位都有高亮，右侧显示选择数量和成员。

战术视图中，敌我所有舰船名字下方都显示血条和当前/最大耐久；本方为绿色，敌方为红色。血条随舰船移动和耐久变化更新，交接回合后按新的当前玩家切换敌我颜色。缩远到战略总览时，名字与血条一起隐藏，避免覆盖整张海图。

## 回合与航行

- 左键选舰，鼠标悬停海格预览航线，右键下令。也可按R或点击“航行指令”，用左键下令；再次R退出。
- 每方依次行动，结束本方回合后交接下一方，全部势力行动一次后进入新一轮。当前势力回合开始时，石油补满至当前上限。初始一座母港对应50点；每多控制一座港口，上限增加10点，两座为60点、三座为70点。计算为40基础上限加每港10点，没有港口时上限40。
- 所有本方舰船共同消耗石油。单舰进入普通海格消耗1点；进入浅滩时DD/CL消耗1点，其余舰种消耗2点。数值为本原型规则，不是原作属性。
- 舰船只执行本次移动，不保留跨回合移动计划。单舰只能移动至当前石油可抵达的海格；石油不足时拒绝指令并提示重选，位置和石油不变。
- 框选后右键海图，将选择中心移到目标附近。抵达时保持出发时的相对位置和间距，不旋转或重新排列；舰船途中分别寻路，逐舰轮流推进并逐舰耗油。整组舰船必须有足够石油在本回合抵达，否则整次指令不执行。
- 目标队形遇到岛屿、无效格或未参与移动的舰船时，整体平移到附近能容纳原队形的海域。不能完整容纳或有成员无法抵达时，整次指令不执行并提示重选；不会拆散队形或叠格。相邻舰船短距离移动可使用其他所选舰船即将腾出的格子。
- 右下回合区域固定显示全队石油数值与进度条；选舰详情只显示本舰作战行动，飞机详情显示本中队独立行动力。
- 岛屿和无效格不可通行。可经过友舰，不能在被占据格结束移动；敌舰阻断航线。
- 在海图获得焦点时，Tab或“下一艘”切换待指挥舰船，Enter结束本方回合；交接时清空多选。
- “本回合待命”结束该舰本回合操作，不消耗或退还石油；“持续驻留”保持停泊，直到唤醒。唤醒不会退还已用的作战行动。
- 多选属于临时选择，没有绑定、旗舰或3～6艘数量限制；之后可单独重新选舰下令。窄航道逐舰通行，终点需要能容纳出发队形。待命、驻留舰船不参与本次移动并显示提示，可在多选面板唤醒舰船。

移除自动航线后的浏览器检查见 `output/instant-movement-browser-verification.json`。回合开始补满石油后，舰船仍在原地等待新指令；当前移动路径预览只显示本回合的石油费用，不显示预计到达回合。

## 基础海战

- 每艘舰船每回合有1次独立“作战行动”，不会因航行而消耗。选中面板同时显示舰体耐久、装甲、石油与本舰作战行动。
- 选择舰炮或鱼雷后，海图会标出可攻击敌舰；悬停目标显示预计伤害、剩余耐久及是否会被击沉，左键敌舰执行攻击。
- DD主炮1～3格、CL主炮1～4格、CA主炮1～5格、BB主炮2～7格；DD/CL/CA鱼雷均为2～5格。CV/CVL改为起飞独立中队。
- 舰炮与鱼雷的射线会被中间岛屿阻挡；鱼雷使用后冷却1个本方回合。炮弹、鱼雷与航空炸弹使用复制的原始透明贴图，由游戏代码实现弹道与命中表现。
- 伤害按轻、中、重装甲固定结算，没有随机命中。防御姿态消耗作战行动，使每次受到的伤害减少2点，持续到下次本方回合开始。
- 耐久归零即沉没。沉没舰退出占格、小地图和当前多选，其他舰船的位置保持不变。

敌舰必须在本方共享视野内才能被选为攻击目标；战列舰7格射程可以使用前方友舰或飞机提供的视野。持续驻留不提供防御加成。

## AI与席位

- 主界面“单人对战”默认1号席位为玩家，其余启用席位为AI；“本地对战”默认全部为玩家。设置页列出8个席位，可在玩家与AI间切换，参战势力数以外的席位显示为空位。至少保留1个玩家席位。
- AI使用与玩家相同的50点基础石油、作战行动、射程、岛屿遮挡、战争迷雾、资金和港口规则，不读取未发现港口或隐藏敌舰。
- AI会优先补充可负担的损失舰、维修港口附近的重伤舰、攻击可见目标和占领近旁港口；随后向已知目标推进，驱逐舰与轻巡洋舰优先探索视野边缘，低耐久舰向本方港口撤退。没有合适攻击的舰船会进入防御姿态。
- AI航母按母舰原国家起飞对应战斗机、轰炸机和鱼雷机。中队优先攻击当前可见目标，没有目标时向已知非本方港口或海域中心侦察，仍按六角格逐格消耗本中队行动力。
- 玩家结束回合后，AI回合使用不透明的“AI COMMAND”等待幕覆盖海图、单位详情、石油与行动结果，并锁定全部作战控件；暂停AI回合时仍保持遮蔽。AI完成命令和动画后自动结束回合，交接回玩家才显示更新后的战场。多个AI席位会依次行动，直到轮到下一位玩家。
- 席位控制写入version 15存档。载入version 1～14旧存档时，所有席位迁移为玩家，避免已有本地战局被AI自动接管。

规则报告为 `output/ai-rules-check.json`，浏览器实测报告为 `output/ai-browser-verification.json`。

## 港口、维修与增援

- 点击海图上的港口标记，右侧切换为该港口的独立管理面板，展示归属、位置、收入、增援名额以及占领、维修和增援操作。顶部“⚓ 港口与增援”提供已发现港口目录，“管理”定位并选中对应港口。
- 每座港口分别记住本次战局内选择的港内舰船和增援舰型，切换港口互不改变；执行占领、维修和增援后继续管理当前港口。资金和石油仍由队伍共用，每轮增援名额按港口独立计算。刷新或重新载入战局后重新选择管理对象和舰型，不新增生产队列。
- 港口的图标、底色、名称及小地图方形标记随已知归属显示对应队伍颜色，中立港口为金色；占领后即时更新。选中港口有外圈，小地图同步突出所选港口；同格有舰船时港口标记向侧面错开，舰船和港口可分别点击。港口选择不参与舰船框选、移动或攻击，点击单位或拖框即可切回单位指挥。
- 每方开始拥有一座母港，群岛间分布中立港口。所有港口必须位于紧邻陆地的海格，并至少有3个相邻海格，保留维修增援泊位；船和飞机的原通行规则不变。512×512八方地图有263座港口。
- 本方可作战舰船进入港口1格内，清除该港口1格内所有敌舰后，可用1次作战行动占领中立或敌方港口。不消耗石油或资金；飞机不能占领。
- 每方初始资金40，每次进入本方回合，每座当前控制港口增加10资金；新占港不立即发钱。资金用于维修和增援。占港立即使石油上限增加10，但不补充当前石油，下次本方回合才补满；失去港口立即降低上限，剩余石油高于新上限时截到新上限。港口不改变飞机独立行动力或舰船作战行动。
- 受损舰在本方港口1格内，可用1次作战行动修复最多4点耐久，每点花2资金；费用不足则不执行。没有自动维修，沉没舰通过增援补回。
- 增援选择本方已损失舰型：DD20、CL30、CA40、BB60、CV70、CVL50资金。每港口每轮最多提供1艘，易手不重置当轮名额；港口本格或相邻海格必须有空泊位，失败不扣费。
- 增援到港后处于“增援待整备”，下次本方回合才能移动或作战，无法提前唤醒。以满耐久替换原舰船实例，清除原防御、冷却和该旧航母仍关联的飞机；已转移到其他母舰的中队保留。当前每方每个代表舰型最多1艘，增援用于补回损失，尚未开放同型多艘造舰或永久机库战损。
- 港口本身不提供视野；拥有的港口位置始终可查，可通过增援重新获得舰船视野。其他港口只在发现后显示，视野外仅显示最后记录的拥有者，不泄露后来易手；失去本方港口会立即报告。

控制全部初始母港，或淘汰其余阵营即可获胜。阵营只有在没有存活舰船且没有港口时才被淘汰，有港口就可以等待收入并增援；飞机不能单独保住阵营。回合交接跳过淘汰阵营，所有阵营都失去舰船与港口时为平局。结算后停止移动、攻击、生产和飞行模拟，仍可查看海图、查看结算、导出战局或建立新战局；胜方存活小人播放原生胜利动作。

规则报告为 `output/ports-verification.json`，实测报告为 `output/ports-browser-verification.json`；`output/ports-demo.json`、`output/ports-victory-demo.json` 和 `output/ports-elimination-demo.json` 分别用于维修增援、母港胜利与淘汰胜利场景。导入会替换当前自动战局，测试前请先保存或导出。

## 战争迷雾

- 舰船提供6格视野，所有航空中队提供8格视野；同一玩家共享视野，其他玩家分别记录。原作国家不影响共享视野。
- 未探索海域完全遮蔽，已探索但离开视野的地形变暗，当前可见海域正常显示。第一版视野按六角距离计算，岛屿不遮挡侦察；舰炮与鱼雷仍保留岛屿弹道阻挡。
- 敌舰、敌机、名字和血条仅在当前视野内显示，小地图也隐藏视野外敌舰；探索记录只保留地形，不保留敌方旧位置。未探索格不显示地形名称、敌舰信息或伤害预览。
- 舰船只能沿当前可见海域移动，向视野边缘分段下令可继续探索，每次仍按石油结算；框选共同移动也受相同限制。飞机可以飞进未知海域侦察，逐格消耗自身行动力，视野随抵达的格子更新。
- 航空追击目标丢失视野后转为待命，不追踪目标的隐藏位置；若已经开始飞向下一格，先完成这一格。其他玩家回合，停留中的本方飞机仍提供视野。
- 回合交接后地图与小地图切换到当前玩家的视野；海图标题显示已探索比例。此版本是本地轮流指挥，联网时的服务端信息隔离留待多人阶段。

规则报告为 `output/fog-verification.json`，浏览器实测报告为 `output/fog-browser-verification.json`；`output/fog-demo.json` 提供近距离接敌、撤离和航空侦察场景。

## 航母与实时中队

- 舰船继续采用回合制；本方飞机在本方回合实时执行指令，交接后该方飞机停止移动；战斗机仍能自动防御拦截。海图顶部“暂停飞行”暂停所有实时航空模拟，包括自动拦截，“暂停动画”控制表现动画；暂停不改变结束本方回合时的续航结算。
- 选择企业或独角兽，在选舰面板滚动查看固定的舰载机国家和“起飞”按钮。正航CV拥有战斗机、轰炸机、鱼雷机3个中队，每队4机、起飞行动力20点、4回合续航；轻航CVL拥有战斗机与鱼雷机2个中队，每队3机、起飞行动力15点、3回合续航。
- 海图标签和选中标题统一使用“战斗机-4机”“轰炸机-3机”“鱼雷机-4机”等形式，机数随损失变化。国家和具体机型保留在详情中。
- 续航只在结束该中队所属玩家的回合时减少1；其他玩家回合不扣除，回合内经过多少秒也不扣除。剩1回合时自动返航，到0仍未降落则损失中队；飞机移动和攻击依然实时执行。
- 飞机沿相邻六角格实时移动，点击格内任意位置都会以该格格心为终点；移动、追击和返航均沿格子路线。可以飞越岛屿和舰船，但不能经过地图无效格。格间保留平滑飞行动画，规则位置只在抵达下一格后改变；格间改令先完成当前这一格，不跳格或重新计时。
- 飞机使用本中队独立行动力，每抵达一个相邻格消耗1点，显示整数剩余/上限；移动、追击和有剩余额度时的返航均计费。待命和原地自动拦截不扣移动行动力。最后1点允许完成一格，随后立即停止任务并自动返航，不能重新安排移动或攻击；返航不会因行动力为0而卡住。待命、跨回合、暂停、刷新或读档都不恢复行动力；回收后再次出动属于新中队、新额度。海图标签和选中详情同时显示剩余/上限，详情显示目标格和正在前往的相邻格，海图高亮所在格、下一格和目标格。
- 每中队起飞消耗3点石油，一波出动消耗母舰1次作战行动，每个本方回合至多出动一波。仍在空中的槽位不会重复起飞；下一本方回合可补齐空槽位。飞行过程使用自身行动力与回合续航，不额外扣除石油。
- 飞机按白鹰/美国、皇家/英国、重樱/日本、铁血/德国分类，首批每国各3种代表机型。飞机国家固定为母舰原始国家，不能切换；企业仅用美国飞机，独角兽仅用英国飞机。所有玩家仍可使用完整舰船池，玩家阵营不决定飞机国家。
- 点击海图中的本方中队选择后，右侧显示本中队信息和操作；右键海图实时移动，右键敌舰持续攻击。战斗机还可右键敌方中队执行拦截；轰炸机与鱼雷机不能空战。飞机可越过岛屿，不占舰船海格。

## 状态动画

- 舰船移动时循环移动动画，抵达或待命时循环待机动画；朝向随实际航线调整。
- 普通舰炮、鱼雷播放完整攻击动画；战列主炮优先播放原生`attack_main`，缺少时使用普通攻击。航母起飞播放技能动画。攻击动作不会被移动、待命或回合切换覆盖，播完后回到当时的移动/待机状态；素材尚在加载时也会保留动作请求。
- 弹道在短暂发射准备后出现，抵达目标时触发受击闪光与抖动。当前12个角色没有原生受击动画，因此保留当前骨骼动作并叠加反馈；未来素材若有`hurt`则可直接播放。
- 击沉时在弹道命中后播放原生退场动作，播放完成后保留最后姿态并淡化，不会再切回站立。读取已沉没舰船同样保持退场姿态。
- “暂停动画”同时冻结骨骼动作、舰船移动表现、弹道及命中反馈，继续后从暂停位置播放；战斗规则结算与航空逻辑暂停仍分别控制。暂停时新下达的指令直接显示结果。
- `output/state-animation-demo.json` 提供近距离拉菲、俾斯麦及航母场景，可通过“导入”核对攻击、主炮、沉没和起飞动作；敌方拉菲初始3点耐久。
- 增援替换舰体时重置沉没动画锁定并回到原生待机；战局获胜时完整播放一次胜利动作，正在播放的攻击先完成。
- `npm run check:animations` 用12个实际复制的Spine骨骼文件检查15类状态切换、完整播放、暂停、加载、沉没锁定、增援重置和胜利动作，报告为`output/state-animation-verification.json`；历史海图攻击、主炮、起飞、移动及退场检查见`output/state-animation-browser-verification.json`。

## 工程与构建

`src/hex.ts` 负责六角坐标、邻接与射线，`world.ts` 负责地图数据，`pathfinding.ts` 负责加权A*，`match.ts` 负责舰船、港口经济、胜负和存档，`ports.ts` 负责确定性港口布局与价格，`aircraft.ts` 负责实时航空规则与验证，`fog.ts` 负责各玩家探索与当前视野。规则可以在Node中独立结算。`camera.ts` 负责镜头，`terrain-renderer.ts` 负责地形，`watercolor-textures.ts` 负责载入和缩放水彩海图纹理，`ships.ts` 负责舰船和原贴图弹道，`aircraft-renderer.ts` 负责飞机编队，`fog-renderer.ts` 负责战术与战略迷雾，`port-renderer.ts` 负责港口标记，`campaign-ui.ts` 负责港口操作与结算界面，`minimap.ts` 负责小地图，`main.ts` 接入界面与本地保存。游戏代码没有调用原素材库或提取目录。15张战斗原图独立复制到`assets/combat`，来源和SHA256保存在`data/combat-assets.json`；生成的海图纹理位于`assets/terrain`，提示摘要和SHA256保存在`data/art-assets.json`。

## 文件组织

```text
assets/ships/<ID>/default/   原文件名的 .skel、.atlas、PNG图集、__preview.png
data/roster.json             游戏可读取的身份、素材路径、动作列表与动作映射
data/source-receipts.json    原始编号、来源路径、元数据摘要与来源哈希
data/asset-manifest.json     独立复制文件及元数据的 SHA-256、大小
preview/                    离线动作查看页与固定版本播放器
preview/vendor/             PixiJS、pixi-spine及其随附许可文本
output/asset-verification.json    文件完整性、图集尺寸与动作覆盖检查
output/browser-verification.json  当前浏览器加载和动作采样检查
output/playwright/           总览图及浏览器检查截图
tools/                      整理、静态检查、本地预览服务
素材清单.csv                 可用Excel查看的首批索引
```

素材是独立复制文件，没有链接回原库；原始PNG、骨骼、图集、透明预览不重编码、不压缩、不改文件内容。每个角色目录包含自己的完整依赖，可独立复制。原素材库和提取目录保留。

## 接入约定

- 以 `unit.id` 为游戏资源键，以 `ship_group` 记录原角色编号，避免仅按中文名称匹配到同名NPC。
- `assets` 中的路径均相对于项目根目录；文件名及大小写保持原样。
- `faction` 是原角色阵营，游戏的 `owner_id`、`team_id` 在对局状态中单独设置。
- 原装甲类型只作身份参考；当前耐久、装甲与伤害是本原型自建的整数规则，没有导入原游戏等级、伤害或稀有度。
- `animation_map` 提供待机、移动、左右攻击、技能、胜利、退场等语义对应。原素材没有独立受击动作，`hurt` 为 `null`，海图采用外部闪光/抖动；对局获胜已接入原生胜利动作。
- 鱼雷与航空弹药、目标伤害、命中判定由规则层处理，不能从骨骼动作时长推算。缺少专用发射动作时可复用攻击动作，再叠加游戏特效。
- `attack_main` 是战列舰可用的额外动作；没有该动作的角色退回 `attack`。
- 预览为了完整查看不同动作会自动适配画面。正式棋盘需要另行校准脚底位置及各角色大小，不能直接使用预览页的每动作缩放值。

抽查骨骼及首批文件均为 Spine 3.8.99，播放器固定为 PixiJS 7.4.3 / pixi-spine 4.0.6。不要只升级播放器主版本而不检查旧骨骼兼容性。运行库随附许可文本在 `preview/vendor/`，引擎、运行库和原美术素材的授权分别处理。

## 检查与重新整理

```powershell
py -3 tools/verify_assets.py
```

此检查只读取本项目素材，生成静态检查报告。在预览页点击“检查全部动画”可用浏览器重新检查当前复制素材，报告保存到 `output/browser-verification.json`。它覆盖每个动作的5个时间采样，并检查默认待机画面有可见像素；不能代替逐帧美术检查，也不证明大地图性能。

`tools/prepare_assets.py` 仅用于从同级原库重新整理。该脚本需要原素材库、原提取目录及其工具依赖；日常预览和游戏资源读取均不使用它。如果目标素材已被修改，脚本会拒绝覆盖，避免替换后续编辑过的素材。
